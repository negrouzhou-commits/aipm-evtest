# AI 产品经理能力模型（测评尺子）

来源：《AI 产品经理能力模型》——基于 Anthropic、OpenAI、Google DeepMind、Databricks 等公司 2026 年公开招聘职位描述整理而成的能力框架。
本文件是测评的**评分依据**，必须与 `question-bank.md` 配合使用。

---

## 一、五维能力模型

| 维度 | 一句话定义 | 传统 PM 是否已具备 |
|------|-----------|-------------------|
| 技术认知 | 知道模型能做什么、不能做什么、大概怎么做到的 | 通常没有，需要专门补 |
| 产品基本功 | 需求分析、优先级排序、跨团队协作、文档表达 | 已具备，可直接迁移 |
| 数据与评估 | 会定义"效果好"、会搭评测集、会做 badcase 归因 | 部分具备，方法论需重建 |
| 商业判断 | 理解 AI 产品的成本结构，能做取舍和定价决策 | 部分具备，但成本结构完全不同 |
| 伦理与合规 | 知道 AI 产品的风险边界和监管红线 | 基本没有，是新增维度 |

### 各维度及格线 / 优秀线

**技术认知**
- 及格线：能听懂算法工程师说的话，不把"微调"和"RAG"搞混；知道大模型核心缺陷（幻觉、知识过时、上下文窗口限制）；能判断一个需求大致适合用什么技术方案。
- 优秀线：能在方案讨论早期参与技术选型判断（Prompt vs 微调、自建索引 vs 调 API）；能看懂模型评测报告并追问关键指标背后的含义；能和算法讨论训练数据质量对效果的影响，而不是只等结果。

**产品基本功**
- 及格线：需求分析、竞品分析、优先级排序、PRD 撰写、跨团队协作、项目推进（做过 1-2 年 PM 基本达标）。
- 优秀线：能把基本功"翻译"进概率性系统——需求分析多问一句"这适合用 AI 吗、多高准确率算够用"；交互设计要设计"AI 自动处理 vs 转人工"的分流机制；PRD 里明确写出允许的错误率和兜底设计。

**数据与评估能力**
- 及格线：理解"没有评测集就没有迭代"；知道要分开看"检索/召回准不准"和"生成/回答好不好"；能读懂准确率、召回率、TTFT 等指标并说出对体验的影响。
- 优秀线：能从零搭评测集（用例从哪来、标准答案怎么定、主观题人工评 vs LLM-as-a-Judge）；能设计 badcase 收集—归因—分发—验证闭环；能区分"模型指标涨了"和"业务指标涨了"是两件事并知道为何脱节。

**商业判断**
- 及格线：理解 AI 产品成本结构与传统 SaaS 不同（每次请求都有边际推理成本）；知道模型选型要在效果、成本、延迟之间权衡，而不是无脑选最强模型。
- 优秀线：能主导模型选型决策框架设计；能设计缓存、蒸馏、小模型路由、分级服务等降本方案；能参与定价与商业化策略设计。

**伦理与合规意识**
- 及格线：知道典型风险（内容安全、隐私、歧视性输出、未成年人保护、误导性使用）；知道公司内部谁负责把关（法务、安全团队）；遇红线知道升级而非自己拍板。
- 优秀线：能在设计阶段主动识别风险点并设计缓解方案（免责声明、人工复核节点、内容审核流程、使用时长提醒）；能读懂并应用适用监管要求。

#### 监管要点（2026 年适用，追问时可用）
- 《生成式人工智能服务管理暂行办法》：内容安全义务、规范数据标注质量。
- 《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行）：针对 AI 陪伴/情感陪护类，须弹窗提示"正在与 AI 交互"、连续使用超 2 小时须提醒、不得设置退出障碍。
- 欧盟《AI 法案》：多数条款 2026-08-02 起适用；高风险义务推迟至 2027-2028 年。按风险分级，高风险场景（招聘、信贷、医疗等）需风险管理、数据治理、人类监督、透明度、日志与文档。
- NIST AI RMF：即使不在欧盟辖区，也是好实践框架。

## 二、「熟悉大模型」三档定档（L1 / L2 / L3）

| 档位 | 能稳定做出来的事 | 面试里通常站不住的回答 |
|------|------------------|------------------------|
| **L1 · 概念可用** | 说清大模型擅长/不擅长什么；知道 token、上下文窗口、温度对体验的含义；亲手调过 1-2 个主流 API | 只会背术语表，说不出"对产品设计意味着什么"；被追问"为什么不适合上 LLM"只会复述"会幻觉" |
| **L2 · 方案可判** | 能用 PM 语言讲清 Transformer/注意力对长文本、延迟、成本的工程含义（不必推公式）；面对场景能在 Prompt / RAG / 微调 / Agent 间给出有依据的初判 | 只会说"都试一下"或"听算法的"；选型理由停在"效果更好"四个字 |
| **L3 · 选型可辩** | 业务目标扔过来能倒推约束（效果底线、延迟、成本、合规），与算法平等讨论候选方案与取舍；能解释"为什么不用大模型"同样有依据 | 只会站队"用最强模型"或"必须自研"；被追问"凭什么这么选"拿不出评测/成本/风险证据 |

**30 秒自测是否过 L2**：研发说"这个需求不适合用大模型"。若只能点头或反问"那还能不能做"，多半还在 L1。若能追出第二层原因（延迟扛不住 / 单位成本算不过来 / 数据不够或分布漂移 / 合规可审计性硬约束），通常已过 L2。

**岗位对标**：应用型 AI PM 把 L2 做稳通常够用；冲模型厂商 / 平台岗需要 L3。

## 三、评分规则（严格照此执行，保证跨次测评可比）

### 单题 1-5 分

| 分 | 判定 | 标准 |
|---|------|------|
| 1 | 明显不足 | 答非所问、核心概念错误、只背术语说不出产品含义、空答或放弃 |
| 2 | 接近及格 | 方向对，但缺关键约束；只讲概念不讲取舍；只有抽象原则没有落地动作 |
| 3 | 及格 | 命中该维度及格线要点，能说清"是什么"和基本的"为什么" |
| 4 | 良好 | 及格要点全覆盖，且至少命中 1 个优秀要点（量化 / 取舍 / 闭环 / 具体场景） |
| 5 | 优秀 | 及格要点 + 优秀要点全覆盖，能落到具体场景、指标、决策证据，有自己的判断 |

**加分信号**：给出数字或量级估算、点名具体指标、主动说"什么情况下不做"、提到失败/兜底路径、引用自己真实经历且能说清结论。
**减分信号**：只堆术语、把"效果更好"当理由、回避取舍、把 AI 当万能解、说不出兜底方案。

### 维度得分 = 该维度所有题目平均分

| 维度分 | 档位 |
|--------|------|
| < 2.5 | 未达及格线（短板，优先补） |
| 2.5 – 3.4 | 及格线附近 |
| 3.5 – 4.4 | 及格与优秀之间 |
| ≥ 4.5 | 优秀线以上 |

### 总分 = 五维平均分（等权）

### L1 / L2 / L3 自动定档算法

记 T=技术认知分、E=数据与评估分、B=商业判断分、P=产品基本功分、S=伦理与合规分。

```
若 T < 2.5                      → 未达 L1（概念层就有缺口）
若 2.5 ≤ T < 3.5                → L1 · 概念可用
若 3.5 ≤ T < 4.5                → L2 · 方案可判
若 T ≥ 4.5 且 B ≥ 4.0           → L3 · 选型可辩
若 T ≥ 4.5 且 B < 4.0           → L2+（技术够，但成本/取舍证据不足，差一口气到 L3）
```

补充约束（写入报告的"定档说明"）：
- 若 E < 2.5，即使 T 达标也降一档说明——"方案判断缺少评测证据支撑"。
- 若 S < 2.5，在报告中单列风险提示，不影响档位。

## 四、短板排序规则

按维度得分升序排列；同分时按以下优先级打破平局（越靠前越优先补）：
**数据与评估 > 技术认知 > 商业判断 > 伦理与合规 > 产品基本功**

理由：数据与评估是 AI PM 区别于传统 PM 的核心硬技能且方法论需重建；技术认知是入门门槛；产品基本功通常可迁移，最后补。

## 五、提升建议库（按维度 × 当前档位取用）

只给**2-4 周内可验证**的具体动作，不给空泛的"多学习"。

### 技术认知
- 未达及格 / 及格线附近：读完一份主流模型 API 文档并亲手调通 1-2 个调用；整理一页「大模型能力边界清单」（擅长/不擅长/典型失败模式）。
- 及格与优秀之间：选一个真实工作场景，写一页「方案选型备忘」——目标、失败可接受度、候选路径（Prompt / RAG / 微调 / 不上 AI）、放弃理由；再用 10-20 条样本做最小对照实验。
- 优秀线以上：参与或旁听一次真实选型会，会后写清「约束 / 候选 / 取舍 / 复盘」四栏；补一份粗算的 token 成本与延迟预算，能被别人挑战。

### 产品基本功
- 未达及格 / 及格线附近：把最近一份 PRD 改写成"概率性 PRD"——补上允许的错误率、失败模式清单、每种失败的兜底路径、成本与延迟预算。
- 及格与优秀之间：为一个 AI 功能画「自主权阶梯」（建议 → 起草 → 执行），给每个动作标注可逆性、错误代价、确认机制。
- 优秀线以上：练"一页纸讲清 AI 功能"（目标用户 / 核心场景 / 成功标准 / 不做的事），并对一个已上线功能做一次复盘。

### 数据与评估
- 未达及格 / 及格线附近：从零建一个 20-50 条的最小评测集，自己写用例和判定标准，覆盖常见案例 + 你最怕的边界案例。
- 及格与优秀之间：跑一次完整 badcase 闭环——收集 30 条线上失败样本，人工读一遍，聚类成失败模式，按占比排序，把 Top 模式写进评测集并定指标。
- 优秀线以上：搭一个 LLM-as-a-Judge，并用 100 条人工标注验证它（算一致率、查位置偏见与冗长偏见）；建立线上"离线指标 vs 线上指标"背离告警。

### 商业判断
- 未达及格 / 及格线附近：给手上一个 AI 功能算一笔账——单次调用的输入输出 token 量 × 单价 × 日调用量 = 月度成本，再除以 MAU 得到人均成本。
- 及格与优秀之间：写一份「自建 vs 调 API」决策备忘，覆盖效果、成本、延迟、数据护城河、供应商锁定风险、退出路径六个维度。
- 优秀线以上：设计一套分级路由 / 缓存 / 输出长度封顶的降本方案，给出预估降本比例与质量损失上限，并算出毛利率敏感点。

### 伦理与合规
- 未达及格 / 及格线附近：列出自己产品适用的国内监管要求清单，标出每条对应的产品动作；查清公司内部法务/安全团队的对接人和升级路径。
- 及格与优秀之间：做一次红队测试——准备 20-30 条对抗性输入（越狱、提示词注入、越界请求、敏感话题），跑一遍并记录失败，把失败永久加入评测集。
- 优秀线以上：把公平、隐私、透明写成 PRD 的验收标准（分人群评测切片与阈值、数据最小化与留存、AI 参与披露），并建一套上线前合规门禁清单。
